# 通知接続設計（未接続）

## 今回の実装範囲

通知時刻の希望を端末に保存するUI、正確な日次完了モデル、接続時に使える RailVocab.notificationSnapshot(vocabulary, now) を用意しています。通知権限の要求、Push購読、ネットワークへの同期、VAPID鍵・端末認証の生成は行いません。バックアップに通知希望が含まれていても、接続済み・有効とは表示しません。

通知対象の日付はAsia/Tokyoです。通常のTOEIC問題の回答や、語彙の自由な見直しだけでは日次完了にしません。開始時に固定した、その日のすべての項目の回答と自信の確認が必要です。誤答・迷いも実施済みには数えます。

## 最小のサーバー構成

1. HTTPS API：端末の登録・認証、Push購読の登録／解除、設定と日次完了の同期。
2. 小さな永続DB：端末、通知希望、購読、日付ごとの完了状態、配信の一意キー、同期世代と連番。
3. スケジューラー：毎日11:00 / 12:00 / 13:00 UTC（日本時間20 / 21 / 22時）。
4. Web Push送信処理と秘密情報の安全な保存領域。

本番フロントは引き続きGitHub Pagesです。サイトの移転は不要です。サーバーは必要な端末状態だけを受け取り、英単語の回答内容や旧TOEICの全履歴を収集する必要はありません。

## 接続時の画面・権限フロー

- 接続先が未設定、API確認が失敗、未購読、許可が未確定の場合は「有効」と表示しない。
- サーバー接続と送信内容を案内し、利用者が通知開始ボタンを押す。
- iPhoneではホーム画面に追加したPWAから、利用者の操作で通知を許可する。
- 許可後にPush購読を作成し、端末ごとに認証されたAPIへ登録する。
- サーバー保存の成功を確認できた場合だけ「通知有効」と表示する。
- OFF操作、購読失効、権限取り消しを扱う。解除はサーバーからも配信を止める。

このフローの実装・実行は次段階です。今回のチェックボックスは希望の保存であり、通知開始ボタンではありません。

## 同期契約案

認証は、承認後にサーバーが発行する端末専用の限定権限を使います。GitHubトークンやVAPID秘密鍵をフロントやlocalStorageに置きません。APIは本番originを限定し、入力検証、サイズ制限、レート制限、再送対策、購読URLの検証を行います。

クライアントから送る最小の日次スナップショット：

```json
{
  "version": 1,
  "day": "2026-10-05",
  "timezone": "Asia/Tokyo",
  "hours": [20, 21, 22],
  "wanted": true,
  "revision": 12,
  "started": true,
  "total": 8,
  "confirmed": 8,
  "complete": true,
  "completedAt": 1791198000000
}
```

値は説明用です。実装関数のcompletedAtは実際の最後の確認時刻で、completeは固定ID集合の確定済み回答から計算します。未開始・空の課題・未確定回答だけではcompleteをtrueにしません。

登録時には、別途 deviceId、同期用generation、端末認証、Push購読をやり取りします。これらは今回生成していません。

- revisionは端末内の変更検出用。現在のrevisionだけをグローバルな順序番号として信頼しない。
- APIの応答に受理したgeneration / revision / day / completeを含める。
- 送信するスナップショットは端末に永続化し、オンライン復帰・再表示時に再送する。古いものを重複送信しても同じ結果になるようにする。
- 同じgenerationでは古いrevisionを拒否。同じ日で受理済みの完了を古い未完了スナップショットで戻さない。
- バックアップ復元・リセット・再登録時はサーバーとの再同期を必要とする。バックアップから古いrevisionが戻るため、認証済みの新generationを発行し最新全体像を照合する。
- 通知資格情報は教材バックアップに含めない。将来追加する資格情報も別の認証領域で管理する。
- 複数端末の「同じ利用者」は今回定義していない。初期最小構成は端末単位。端末間で共通の完了停止が必要なら利用者の対応付けを別途設計・承認する。

## 配信判定

各時刻の直前に、サーバーは次を確認します。

1. その端末の通知が有効で、利用可能なPush購読がある。
2. 日本時間の対象日が正しく、その日の完了が受理されていない。
3. 端末ID＋日本時間の日付＋時刻の配信キーが未処理である。
4. ロック／トランザクションで配信キーを確保し、送信直前にも完了状態を再確認する。

20時・21時・22時のそれぞれで判定し、20時までに完了が同期された日は送らず、20時以降の完了なら残りを止めます。23時以降や翌日に持ち越して再通知しません。期限切れ購読は無効化します。リトライのTTLも対象時間帯を越えないようにします。

全通知を無条件に送って端末で破棄する方式、Service Workerのタイマー、端末が閉じていても動くと仮定したsetTimeoutは使用しません。

## オフラインと配信の限界

完了はオフラインでも端末に保存できますが、サーバーに届くまではその完了を配信側が知ることはできません。通信が途切れたままの即時停止は保証できません。UIには「この端末で完了／配信停止への同期待ち」と「サーバーにも同期済み」を区別して表示する必要があります。

サーバーが配信基盤へ受理させた通知は、その後に完了が同期されても取り消せない場合があります。送信直前の再確認と短いTTLで範囲を絞ります。この仕様を利用者と確認してから接続します。

## 接続前に必要な承認

- サーバー事業者・アカウントの使用、無料枠と上限、課金が必要な場合の承認。
- VAPID鍵と端末認証の生成・保存、運用責任者。
- Push購読・端末識別子・通知希望・日次完了をサーバーへ送信する範囲と保持期間。
- 通知の購読と端末許可を利用者自身が行う段階。
- オフラインで未同期の場合と送信直後の停止の限界。

通知配信を使わなくても、語彙・熟語モードは完成状態で使用できます。
