# Rail English 1.2.0

スマートフォンで単語・熟語を毎日学ぶ、静的なオフライン対応PWAです。公開先は従来どおり https://anthra2525.github.io/rail-english/ です。Sitesは使用しません。

## 単語・熟語モード

- ホームの主な学習モード。単語80項目＋熟語・定型表現40項目を収録。
- 意味の4択 → 業務場面の例文・和訳・コロケーション → 自信の確認。
- 新規は1日5項目が初期値です。設定で3 / 5 / 10 / 15項目に変更できます。期限到来の復習は別枠で全件追加します。
- 両方の未学習項目が残っている間、初期値では新規の単語3・熟語2を選びます。
- 今日の課題は最初に開始した時点で固定します。設定変更、ホームへの移動、再読込では入れ替えません。
- 日本時間の日付ごとに、すべての異なる項目について「回答＋自信の確認」が終わると日次完了です。
- 間違い・迷いも実施済みに数えますが、習得状況とは分けます。開いただけ、回答だけ、同じボタンの連打では完了しません。
- 確認前に日本時間の翌日になった回答は前日・当日の完了に加算しません。確定済みの履歴は残ります。ホームから今日の課題を始めてください。
- 復習間隔は1 → 3 → 7 → 14 → 30日。期限到来時の自信のある正解に限り、同じ学習日に一度だけ進めます。
- 期限前の正解では元の期限を延ばしません。間違い・迷いは翌日までに再確認します。
- 30日間隔への到達は学習の目安で、永久に覚えたことを意味しません。

従来のTOEIC問題はホームの「TOEIC問題モード」から利用できます。300問の問題本文・問題IDは変更していません。旧モードの復習アルゴリズムは今回の変更対象外です。新しい語彙履歴に旧問題の正答を移すことはありません。

## データと互換性

保存キーは **rail-english-v1** のままです。既存の attempts / progress / extraQuestions / settings / session と追加フィールドを保持し、独立した vocabulary フィールドを追加します。旧中断セッションと新しい日次課題は並行して保存できます。

vocabulary.days は日本時間の日付ごとの固定項目・回答・完了時刻、vocabulary.progress は語彙だけの復習状況、vocabulary.attempts は自信の確認まで確定した履歴です。自由な見直しは日次完了に加算しません。

cleanState は新旧バックアップを受け付け、トップレベルと有効な履歴・設定・セッションに含まれる未知フィールドも保持します。新語彙データの非対応スキーマ・不正な構造は読み込みを止め、元のlocalStorageを上書きしません。設定から元データを書き出せます。

バックアップ全体の形式とschemaVersionは1を維持します。**1.2.0で作った語彙履歴入りバックアップは1.2.0以降で復元してください。** 旧版1.1.0のcleanStateでは新フィールドが失われます。公開版を旧版へ戻す前にも必ずバックアップしてください。

公開origin/path、manifestの id / start_url / scope は変更しません。違うURLや端末のlocalStorageとは別の保存領域になります。

## 通知

現在は **未接続・通知されません**。設定で保存するのは、接続後の通知希望だけです。

- 希望時刻は日本時間20時。未完了なら21時・22時。
- 日次完了をサーバーが受信したら、その日の以後の配信を停止する設計。
- 今回は通知許可の要求、Push購読、外部送信、アカウント作成、鍵や永続認証の生成を行いません。
- GitHub Pagesの静的配信だけではアプリを閉じた後の定時通知は行えません。

最小構成・同期契約・別途承認が必要な作業は [通知接続設計](docs/notifications.md) を参照してください。

## 起動

ビルド・npmインストールは不要です。Nodeで同梱の開発サーバーを起動します。

```powershell
node .\dev-server.cjs
```

http://127.0.0.1:4173/rail-english/ を開きます。Service Workerのためfile URLではなくlocalhostを使用してください。

今回のDドライブ限定環境では、次のコマンドで起動できます。

```powershell
Set-Location 'D:\Codex\rail-english-vocabulary-2026-10-06\app'
& '..\tools\node.exe' '.\dev-server.cjs'
```

初回に「オフライン準備完了」を確認してから圏外で再読込してください。公開時はHTTPSが必要です。

## 検証

```powershell
node --test .\tests\core.cjs
```

依存のないNodeテストで、日付境界・復習間隔・日次完了・旧データ移行・バックアップ往復・教材の基本整合性を検証します。

今回の作業フォルダーではブラウザー試験も再実行できます。

```powershell
& '..\tools\node.exe' '.\tests\browser.cjs'
& '..\tools\node.exe' '.\tests\upgrade.cjs'
```

browser.cjs は4173番の開発サーバーを使用します。upgrade.cjs は4174番に一時サーバーを起動し、同階層のbaselineから旧版を配信します。ブラウザー試験用のPlaywrightとChrome for Testingは作業フォルダーのtools内にあり、アプリの公開資材には含めません。スクリーンショットとJSON結果は同階層のverificationに保存します。

実機のiPhone / ホーム画面追加 / Web Push配信は未確認です。通知の接続は未実装です。

## 公開手順

1. 現行公開版で学習記録をバックアップします。
2. リポジトリの最新mainとローカルの未保存変更を確認し、作業ブランチで差分を適用します。原本は64ca2cc63203ae0d535e95873824189e6d84ec93です。
3. テストと画面レビューを行います。GitHub Pagesの公開元ブランチ・フォルダーは既存設定を確認して維持します。
4. 公開の承認後にだけコミット・push・必要なレビュー／マージを行います。現在の公開先を変えません。
5. index.html、vocabulary-*.js、sw.js、manifest.webmanifest、iconsを同じルートに配信します。HTMLとSWのバージョンを同時に更新します。
6. 公開URLで更新を確認します。既存PWAの設定に更新ボタンが出た場合は、進行中の回答の確認後に更新します。旧TOEICの中断セッションは旧版の更新UIでは完了が必要です。
7. 同じ端末・公開URLで履歴の維持、今日の課題、オフライン再起動を確認します。

公開先とGitHub Pagesの既存設定を維持してください。通知バックエンドは未接続です。公開操作は利用者が承認した範囲でのみ行います。
